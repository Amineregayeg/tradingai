# PRODUCTION RUNTIME PINS — the exact set the VPS installs.
#
# THIS FILE IS THE DEPENDENCY LIST. It has three consumers and no rivals:
#
#   1. the api container on the VPS — `pip install -r /app/requirements-prod.txt`
#   2. pyproject.toml — reads it via setuptools dynamic metadata, so
#      `pip install -e ".[dev]"` resolves the same versions
#   3. CI — installs through (2) and then asserts the strategy-critical
#      packages match this file exactly
#
# HOW IT GOT THIS WAY, so nobody re-introduces the second list:
# The api used to carry ~20 inline `pkg==version` pins in its command block in
# /docker/tradingai/docker-compose.yml — a file not in this repo. The versions
# actually running were therefore invisible here, and the suite had never once
# been run against them. That is how production came to run numpy 2.2.6 and
# pandas 3.0.2 while pyproject.toml declared numpy<2.0.0 and pandas<3.0.0 —
# a pair so contradictory that `pip install -e .` failed outright.
#
# Both halves are now closed: pyproject reads this file instead of declaring its
# own ranges, and the VPS installs from it instead of an inline copy (C1).
# .github/workflows/ci.yml fails the build if inline pins reappear in the
# committed compose.
#
# Changing a version here changes production on the next `--force-recreate`.
